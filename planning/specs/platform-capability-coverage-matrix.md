# Platform Capability Coverage Matrix

This matrix is the maintained inventory of backend responsibilities implied by Human Capital Management Suite. It prevents architectural mentions from being mistaken for owned systems and prevents `DEFERRED` from being mistaken for forgotten.

## Coverage States

```text
DEFINED
  focused contract identifies authority, state, APIs, failure semantics,
  evidence, security, and phase depth

PARTIAL
  meaningful contract exists, but an important responsibility or lifecycle
  remains underdefined

IMPLIED
  behavior is mentioned or assumed by another plane, but no owner contract exists

MISSING
  responsibility has no meaningful architectural treatment

DEFERRED
  boundary and non-goal are explicit; implementation is intentionally postponed
```

Coverage and implementation depth are independent:

```text
DEFINED + OUT OF PHASE     healthy long-term boundary
MISSING + PHASE 1 NEED     release blocker
IMPLIED + IMPLEMENTING     architecture debt and duplication risk
```

Each row must name a contract owner, evidence link, implementation depth, next closure action, and review trigger. A row moves to `DEFINED` only through review of the focused contract or equivalent executable schemas/tests—not because its name appears in a diagram.

## Promoted Foundation Set

These responsibilities receive explicit architecture ownership now because several domains would otherwise reinvent them:

```text
Human Work --------+
Forms -------------+----> reusable business interaction services
Business Rules ----+

Master/Reference --+
Schema Registry ---+----> governed shared definitions
Crosswalks --------+

Import/Migration --+
Managed Files -----+----> enterprise data movement
Messaging ---------+

Tenant Lifecycle --+
Support Access ----+----> customer operations and trust
DLP/Egress --------+

Conformance -------+----> evidence that shared contracts still compose
```

Promotion means a named owner, charter, coverage row, dependency placement, phase depth, and review trigger. It does not mean full Phase 1 implementation.

## Review Process

Review the matrix:

- When a new subsystem, connector, workflow primitive, or product domain is proposed
- Before each phase/authority gate
- After reference-workflow or incident analysis reveals an assumed responsibility
- When a row marked `IMPLIED` becomes a delivery dependency
- Quarterly while the architecture is changing rapidly

```text
new requirement / incident / workflow
              |
              v
search coverage matrix + dependency graph
              |
   +----------+----------+
   v                     v
owner exists          responsibility missing
   |                     |
update contract       create row + owner + scope decision
   +----------+----------+
              v
reference/conformance fixture
```

The matrix is not an assertion that all gaps are known. Its purpose is to make newly discovered responsibilities cheap to classify, own, and sequence without pretending the inventory is exhaustive.
