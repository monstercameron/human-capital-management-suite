# Local chat pingback demo

Added `tools/chat-pingback/agent.py`, a small local machine client for the existing resource-scoped chat API. It listens for new posts beginning with `@pingback`, ignores its own posts, and posts an echo as a threaded reply. A stable event-derived idempotency key covers duplicate delivery; a local resume-cursor file supports restart. The CLI requires an installed agent identity and token through environment variables, uses only loopback HTTP, requires HTTPS remotely, and offers a dry-run mode. No credential is stored in source or state.

The chat resource now carries optional `parent_id` through the authenticated SendPost port. The service rejects missing, deleted, cross-room and wrong-tenant parents before writing. The CHAT-023 todo remains open because this small demo does not implement its complete ordered navigation, follow state, retained tombstone context or full test matrix.

Verification on Windows/arm64, Go 1.26.3: `python tools/chat-pingback/test_agent.py` passed (3 tests); `go test ./internal/collaboration/chat` passed; `go test ./internal/transport/chatresource` passed. No full repository gates or PostgreSQL integration test were run.

# Channel poll widget

Added one persistent poll per channel with a question, 2–10 distinct options, one replaceable vote per active member, option counts, rounded percentages, and the caller’s own selection. Vote identities stay in the tenant scoped store; RPC reads expose totals and only the authenticated caller’s selected option. The store serializes on the channel conversation row and records create/vote revisions in an immutable, RLS protected audit table. Poll creation and voting both require current channel membership and the routed authorization fence. Migration 00013 and the independent chat storage disposition register cover the new poll and revision tables.

Added the chat extension RPC, application port, accessible channel details UI, native progress bars, form guidance, and English/German/Arabic copy. The UI clears poll state when changing channels and rejects stale/unknown option IDs before calling the vote callback.

Focused chat UI, product copy, application, and transport tests passed with `go test -count=1 -run 'Test(ChannelPoll|ChannelPollCopy)' ./internal/humanwork/chatui ./internal/humanwork/productui ./internal/transport/chatextensions ./internal/application`. The chatstore integration test did not reach PostgreSQL: the shared Windows embedded database startup sweep was contending with another full test suite, so its persistence assertions remain unverified. The port 8888 preview also needs migration 00013 applied to its isolated chat database before create/vote/results can be checked in the browser; CHAT-031 remains open.
